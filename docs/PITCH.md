## Q1 技术栈是什么?

**一句话**:"Python 3.12 + FastAPI/uvicorn 做接入层,Redis 承担全部跨请求状态(限流/鉴权缓存/渠道路由/队列),PostgreSQL 做账本,观测用 Prometheus+Grafana,部署是 Docker Compose,CI 是 GitHub Actions——双数据库方言 67+67 测试全绿。"

展开(按请求链路说,不是背清单):一个请求进来——request_id 注入(纯 ASGI 中间件,
选它不用 BaseHTTPMiddleware 是因为 LiteLLM 实测后者吞 44% 吞吐)→ virtual key 鉴权
(Redis 缓存优先,miss 才回源 PG)→ Redis+Lua 令牌桶准入(一段脚本原子完成限流+
TPM 读数+预算读数)→ 渠道调度(冷却状态机+EMA 延迟路由)→ httpx 转发(SSE 字节级
透传)→ **请求路径到此结束,零 DB 写**;记账走自研 Redis Streams 持久队列(at-least-once
+ 幂等键),Grafana 看 TTFT/分租户分渠道指标。

**不说**:不堆名词;被追问哪个组件就停在那个组件往深讲。

## Q2 怎么实现的?(架构一句话 + 三个设计点)

**一句话**:"网关本体是无状态的——所有跨请求状态都推给 Redis,所以多副本水平扩展
实测 1→4 worker 是 4.04 倍近线性;有状态的部分(账本)走持久队列,崩溃不丢。"

三个设计点(每个都能讲两分钟):
1. **准入单脚本**:限流桶扣减 + TPM 读数 + 预算读数合并成一次 Lua 往返(EVALSHA);
2. **故障转移状态机**:429 立即冷却并尊重 Retry-After、5xx 冷却 60s、EMA 延迟优先
   路由、全渠道冷却返回 503+Retry-After;
3. **at-least-once + 幂等 = 效果 exactly-once**:Streams 消费组/XCLAIM 崩溃恢复/死信,
   账本幂等键 UNIQUE 兜底。

## Q3 是不是 demo?数据哪来的?

**一句话**:"我的数据分三层,每层来源我都能说清——而且 mock 和 real 的口径我严格分列。"

- **网关自身的运行数据**(账本/计数/渠道健康):来自真实请求,不是造的;
- **上游两条口径**:测试与演示走 mock 上游(免费、确定性,让 67 项测试可重复);
  真实口径是 DashScope qwen-flash 冒烟——过网关答题 31/35 token,**花费约 ¥0.00005,
  有 usage 账单**;
- **接入的两个 Agent 应用**:AskBI 的答案来自它自己的电商 mock 数据集(3.1 万小票,
  答案里的 3091 万销售额是数据集真实聚合值);PolicyCompass 的答案来自 16 份真实
  政策语料——**数据归属在两个 Agent 项目里各自交代,网关只做透明转发,不加工数据**。

**绝不说的**:不把 mock 数字说成真实流量;被问"mock 是不是心虚"时反打——"mock 是
可控故障注入的前提,我的 4 个真 bug 全是故障演练抓出来的,真实上游反而抓不到这些"。

## Q4 有没有上线?

**诚实版(背下来)**:"代码层是生产就绪的——compose 一键全拓扑、数据库迁移、
/ready 就绪检查、CI 双方言、上线差距清单都写好了;但我没有公开上线,没有真实用户
流量。这是校招项目和生产系统的真实差距,我不过渡宣称。部署动作我评估过:装
Docker、配 admin token、挂反代,半天内可跑起来;上线后我会补公网实测口径
(公网延迟和本机压测是两个问题)。"

**展开**(如果面试官继续问):上线的价值不在"跑起来",在**流量回来之后能学到什么**
——真实上游的故障分布、真实用户的配额行为、公网 TTFT 分布。这三样是我现在
mock 口径给不了的,所以它们在我的 PRODUCTION_GAP 里被标注为【部署后才能说】。

**绝不说的**:不说"上线了""生产验证过""有用户在用";不把本机压测说成生产性能。

## Q5 还能怎么丰富?(= 你知道它还缺什么)

**一句话**:"还有四件,每件我都写了触发条件——够到量级才做,不为丰富而丰富。"

| 项 | 触发条件 | 一句话方案 |
|---|---|---|
| OTel 分布式追踪 | 多服务拓扑排障需要 span 树 | tracer 挂路由+上游调用,OTLP 导出 |
| 审计日志 | 多人管理台 | admin 操作写追加日志表 |
| MCP HTTP transport | MCP 客户端跨机器接入 | stdio→SSE transport 换皮 |
| PG 账单表分区 | 账本千万行 | PG 方言迁移分支,按月分区 |

再加一层"部署后才有意义"的:公网压测口径、真实用户配额行为分析、Grafana 实盘告警。

**加分句**:"丰富项目的正确方向不是堆功能,是让每个已有主张再多一层证据——
比如我把账本从进程内队列迁到持久队列,不是因为缺功能,是因为审计发现崩溃会丢账。"
